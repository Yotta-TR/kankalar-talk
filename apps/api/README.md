# Kankalar Talk API

NestJS modular monolith for the Kankalar Talk REST API. It targets Node.js 24 LTS and uses npm, PostgreSQL, Prisma ORM 7, Jest, and OpenAPI/Swagger. Text conversation endpoints use a temporary development-only identity and a mock conversation engine. No production authentication, AI provider, audio feature, or payment system is configured.

## Requirements

- Node.js 24 LTS and npm
- A locally available PostgreSQL instance and a database named `kankalar_talk`

No database is bundled or simulated by this project.

## Local setup

From `apps/api`:

```sh
npm ci
cp .env.example .env
```

Adjust `DATABASE_URL` in the local, ignored `.env` file to match your PostgreSQL instance. Do not put credentials in Git or the mobile app. The example URL is for local development only.

The initial migration creates the basic users, conversation sessions, messages, and idempotent message requests tables. Review `prisma/migrations/20261105181800_conversation_storage/migration.sql` before applying it. It is not applied automatically and must not be applied to production without a separate review and approval.

```sh
npm run prisma:generate
npm run prisma:migrate:dev
npm run start:dev
```

`prisma:migrate:dev` applies the migration to the database in `DATABASE_URL`; use only a local development database. `prisma:migrate:deploy` is provided for a separately approved deployment workflow and is not run as part of tests or builds.

The service listens on `http://localhost:3000` by default. `GET /v1/health` is the health endpoint, Swagger UI is at `/docs`, and its OpenAPI JSON is at `/openapi.json`.

The API connects to PostgreSQL during startup. Set `PORT` to change the listening port.

## Development conversation API

Conversation endpoints are available only when `NODE_ENV=development`. Set `DEV_AUTH_USER_ID` to a UUID; the API upserts that user in PostgreSQL and uses it as the trusted identity. This local-only mechanism does not accept a user ID from requests and is forbidden in every other environment.

- `POST /v1/conversations` with `{ "mode": "PRIVATE", "character": "Eren" }` or `{ "mode": "PRIVATE", "character": "Elif" }` creates a private session. `{ "mode": "KANKALAR_ROOM" }` creates a room session.
- `GET /v1/conversations/:sessionId?limit=40` returns the session and recent messages; `limit` may be from 1 to 100.
- `POST /v1/conversations/:sessionId/messages` accepts `clientRequestId` and `text`. Room requests may optionally set `learningNeed` to `practical_conversation` or `encouraging_practice`.

The response is generated by the mock adapter at A1 level. Reusing a `clientRequestId` returns a saved completed response or a conflict for a request that is pending or failed.

## Checks

```sh
npm test
npm run test:e2e
npm run lint
npm run build
```

The tests use a mocked Prisma provider and do not require a running database. Prisma generation reads `DATABASE_URL` from `.env` or the environment; it does not connect to the database.

## Initial module boundaries

- `health`: non-sensitive service health endpoint.
- `auth`: temporary development-only user identity guard.
- `conversations`: authenticated session and message routes over the existing user-scoped persistence.
- `dialogue-coordinator`: role selection and conversation-turn orchestration boundary.
- `ai`: provider-neutral conversation engine port with a temporary mock adapter.
- `usage`: reserved for usage recording and limits; no fake quota or billing behavior.

Eren and Elif instructions are held by the dialogue-coordinator and passed to the AI port as request data. The AI adapter does not own character instructions. The mock adapter is only for local/test scaffolding and is not an educational content source.

Conversation service methods require a trusted user context from the development authentication module. There is no API that accepts a caller-selected user ID. The storage models only the text conversation foundation; additional product schema remains subject to review.
